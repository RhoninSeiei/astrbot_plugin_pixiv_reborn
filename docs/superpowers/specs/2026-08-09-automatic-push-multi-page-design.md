# 自动推送排除标签与多图作品发送设计

## 背景

当前随机标签推送从每条标签字符串解析排除项，画师订阅没有统一的排除标签配置。多页作品在随机推送和画师订阅中只发送第一页；指定作品命令虽然可以发送全部页面，但会逐页产生多条消息。

本次调整包含两个关联目标：

1. 所有自动 Pixiv 推送统一排除 `NTR` 和 `悪堕ち` 标签。
2. 同一作品 ID 的多幅图片作为一个发送单元处理，并以实际发送图片数控制随机推送上限。

## 范围

统一排除标签应用于：

1. 随机标签推送。
2. 随机排行榜推送。
3. 画师订阅推送。
4. 上述类型未来新增的订阅。

手动搜索、LLM 工具和小说功能保持现有过滤行为。多图发送规则应用于随机推送、画师订阅和指定作品查询。普通列表搜索与 LLM 工具继续按每个作品发送第一页，避免改变其数量参数含义。

## 自动推送排除标签

新增插件配置 `automatic_push_excluded_tags`，采用逗号分隔字符串，默认值为：

```text
NTR,悪堕ち
```

配置加载时执行以下规范化：

1. 兼容英文逗号、中文逗号和顿号。
2. 去除首尾空白。
3. 按不区分大小写的形式去重，同时保留原始顺序。
4. 空字符串表示没有统一排除标签。

随机标签推送将订阅字符串中的排除项与 `automatic_push_excluded_tags` 合并。随机排行榜和画师订阅使用统一排除项。匹配继续采用插件现有的标签名称不区分大小写包含判断。

生产配置文件需要显式写入该字段，使 Dashboard 能显示当前设置。现有随机标签数据库记录保持原值，避免把相同排除项重复写入 26 条标签记录。配置启用后，当前 3 个随机推送群与 7 条画师订阅同时生效。

## 多图页面选择

普通插画按以下规则选择页面：

| Pixiv 页面数 | 本次选择页面 | 消息形式 |
| --- | --- | --- |
| 1 | 第 1 页 | 一条普通消息 |
| 2 至 9 | 全部页面 | 一条包含多张图片的普通消息 |
| 10 及以上 | 前 3 页 | 一条包含 3 张图片的普通消息 |

页面数达到 10 时，详情文本增加：

```text
作品ID: <illust_id>
```

现有详情链接继续保留。详情文本在消息末尾附加一次，不在每张图片后重复。动图继续使用现有 GIF 处理，不参与多页页面选择。

## 消息构造与失败处理

一次作品发送遵循原子式构造：

1. 根据页面规则确定本次页面集合。
2. 依次使用现有 `original`、`large`、`medium` 降级策略准备每张图片。
3. 所有页面准备成功后，构造一个包含全部图片组件和一段详情文本的 `MessageChain`。
4. 通过一次 `context.send_message()` 发送该作品。

任意选定页面准备失败时，本次作品不产生可发送消息。随机推送沿用现有三次重试；三次均失败后选择其他候选作品。画师订阅保持游标不变，等待下一次检查。指定作品查询返回现有可读错误消息。

文件发送模式下，如果后续页面准备失败，需要清理当前作品已经生成的临时文件。消息发送完成或失败后，同样使用现有临时文件清理函数处理整条消息中的所有图片组件。

QQ `sendMsg` 已受理但回执等待超时的判定保持现有行为：符合既有成功事件特征时按发送成功处理。

## 随机推送数量与缓存

`return_count` 在随机推送中解释为本次目标图片数。候选作品仍按现有随机顺序选择，规则如下：

1. 发送作品前，如果累计成功图片数已经达到或超过 `return_count`，停止选择候选。
2. 当前作品发送成功后，将实际选择页面数加入累计值。
3. 当前作品可以使累计值超过 `return_count`；该作品保持完整，随后停止选择下一个作品 ID。
4. 页面数达到 10 的作品按 3 张计数。
5. 动图按 1 张计数。

示例：`return_count=3`，前一个作品发送 1 张，第二个作品包含 5 页，则本次共发送 6 张，随后停止。

随机推送结果需要同时携带成功作品 ID 集合与成功图片数。`SentIllust` 只在作品消息发送成功后写入当前作品 ID。以下对象均不得写入缓存：

1. 尚未选择的候选作品。
2. 因数量上限而跳过的作品。
3. 页面准备失败的作品。
4. 消息发送失败的作品。
5. 作为失败替代候选但最终没有发送的作品。

画师订阅继续使用 `last_notified_illust_id`。只有作品消息发送成功时推进游标；被统一排除标签过滤的作品按现有行为推进游标，避免每次检查重复处理明确禁止的内容。

## 代码职责

`utils/config.py` 与 `_conf_schema.json` 负责统一排除标签配置及 Dashboard 展示。

`utils/tag.py` 提供排除标签规范化与合并函数，复用现有标签匹配逻辑。

`utils/pixiv_utils.py` 负责页面选择、一次作品的图片准备、单条消息构造和临时文件清理。

`utils/random_search.py` 负责自动推送排除项合并、实际图片数累计、发送结果记录和成功后缓存。

`utils/subscription.py` 负责画师订阅统一排除项及多图发送。

`handlers/illust.py` 继续让指定作品查询调用多图模式，并采用新的页面上限规则。

## 测试要求

单元测试至少覆盖：

1. 统一排除标签的分隔符兼容、去重和空值。
2. 随机标签自定义排除项与统一排除项合并。
3. 随机排行榜与画师订阅应用统一排除项。
4. 1、2、9、10 和超过 10 页作品的页面选择。
5. 2 至 9 页作品只生成一条消息，图片组件数量等于页面数，详情文本只出现一次。
6. 10 页及以上作品只生成前 3 张，并包含明确作品 ID。
7. 当前多页作品使累计图片数越过 `return_count` 后停止选择下一作品。
8. 未选择、下载失败和发送失败的作品均不写入 `SentIllust`。
9. 成功作品在下一候选处理前写入 `SentIllust`。
10. 文件模式中途失败时清理已经生成的临时图片。
11. 现有 QQ 受理后回执超时行为保持通过。
12. 动图发送行为保持通过。

侧车容器执行完整测试集，并补充语法检查、配置模式解析和目标文件差异检查。

## 生产实施与验证

生产实施保持目标插件范围：

1. 先在 `astrbot-dev-test` 侧车容器执行依赖完整的测试。
2. 备份目标插件文件、插件配置和订阅数据库。
3. 仅同步 `astrbot_plugin_pixiv_reborn` 的变更文件。
4. 显式写入 `automatic_push_excluded_tags` 生产配置字段。
5. 通过 Dashboard API 精确重载 `astrbot_plugin_pixiv_reborn`。
6. 检查插件启用状态、配置摘要、LLM 工具注册、随机任务启动和近期错误日志。
7. 保持 AstrBot 主框架、其他插件及生产容器运行状态不变。

本次无需迁移随机标签数据库内容。数据库仅用于验证现有群和订阅数量，以及确认发送缓存语义。
